# RPS IPL Auction Platform

FastAPI-based shared IPL auction app. The existing interface and auction workflow are retained.

## Local run

```bash
pip install -r requirements.txt
python auction.py
```

Local mode uses `auction.db` (SQLite). To use OCR locally, install Tesseract OCR and optionally set `TESSERACT_CMD` to its executable path.

## Free cloud deployment (Render + Neon)

The Render service must use a persistent PostgreSQL database. Do **not** rely on the app's local SQLite file on Render: the free web service filesystem is ephemeral.

1. Create a free PostgreSQL project on [Neon](https://neon.tech/).
2. Copy its PostgreSQL connection string. Use the pooled connection string if Neon provides one, and ensure SSL is enabled (usually `sslmode=require`).
3. In [Render](https://render.com/), create a new **Blueprint** from this GitHub repository and select the `cloud-deploy` branch.
4. Render reads `render.yaml`. Set `DATABASE_URL` to the Neon connection string when prompted.
5. The blueprint generates `AUCTION_PASSWORD` automatically. The default username is `auction`. Open the Render service's Environment page to view/copy the generated password and share it privately with auction participants.
6. Deploy. The service health check is `/health`.

The app protects the auction page and API with HTTP Basic Authentication. Keep the password private; anyone who has it can modify the shared auction.

### Required environment variables

- `DATABASE_URL`: Neon PostgreSQL connection string. Required on Render.
- `AUCTION_USERNAME`: defaults to `auction`.
- `AUCTION_PASSWORD`: required for a protected deployment; generated by the Render blueprint.
- `TESSERACT_CMD`: optional override for the Tesseract executable. The Docker image installs Tesseract and normally needs no override.

### Notes

- The first request after an idle period may be slow on a free web service because it can spin down.
- Free-tier quotas and policies can change. Check the provider dashboards and do not enable paid services or add a payment method unless you intentionally choose to.
- Playing XI selections are currently stored in each browser's local storage, so they are device/browser-specific; auction purchases, player records, and unsold players are shared through PostgreSQL.
- The `main` branch is not changed by this deployment preparation. Review and merge `cloud-deploy` only after testing.
